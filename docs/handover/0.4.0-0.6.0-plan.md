# Glyph kit 0.4.0 to 0.6.0: plan (approved 2026-11-03, nothing built)

Planned 2026-11-01. The kit is at 0.3.0 on `main`. This plan turns the kit from something Alex uses to draw his own figures into something other people use to show their work to the people they answer to. It replaces the 0.4.0 slot that the UI system held (`docs/ui-system-plan.md` at ca54395, built on the pages-and-layers plan at 32bf2a1). See "What moves out".

## The shift

**Today.** Glyph kit is a skill an agent uses to draw figures for its user, mostly into Markdown, pull requests and decks. The builder on the site lets anyone try one figure, keep it on their device and export it. Its proof points are about the maker: cheaper and faster than HTML/JS for an agent (the 20 October study), the same spec always gives the same drawing, and a changed figure shows up as a changed line.

**After 0.6.0.** Someone who owes a stakeholder an update makes it in minutes from their own numbers and sends one link. That could be a designer, a product manager, a researcher or an engineering lead. The reader opens the link in whatever they use, with nothing to install, and gets the point first. Next week the maker updates the same link, and the reader sees what changed and can answer.

| who | today | after 0.6.0 |
|---|---|---|
| maker | Alex, through an agent | anyone with an update due, in the builder or their own chat assistant |
| reader | Alex, or an engineer reading a pull request | a director, a client or another team, who installs nothing |
| the kit | a skill in a folder, and a builder to try it | a skill, a builder, and links people open |

**What carries over unchanged:** the spec, every type, the same drawing from the same spec, the 80-cell rule, "no source, no numbers", and the SAMPLE DATA stamp. These are what make the kit fit for stakeholders. A reader can trust that a number came from a file someone named, not from a model.

**What the shift costs:** so far the kit's only server work is the drawing and feedback functions. Links that stay current and readers who answer back mean keeping people's data (0.6.0). That's the biggest decision here; see "Decisions for you".

## Before 0.4.0: five real updates

There is no evidence yet about people other than Alex. Before building, give the builder to five people outside who owe someone an update this week. Each makes the update with the kit, sends it, and asks their reader one question: "What did you take from this?" Note where each maker stops, and whether the reader's answer matches the point the maker meant.

This also tests the riskiest unknown: whether a text-drawn page in Departure Mono reads as serious to a director, or as a curiosity. The order of 0.4.0's workstreams follows what breaks.

## 0.4.0: Send it

A figure or a page leaves the builder as something a stakeholder opens with nothing installed.

### 1. A link that carries the page

- The spec is compressed into the link after `#`. Opening the link draws the page in the browser with the kit's own code. Nothing is stored, and the numbers never reach a server, because browsers don't send the part after `#`.
- **Measured on the kit's own examples:** a whole `readout` page needs 490 characters of link; a typical figure needs 262. A page with a large table may need a few thousand. Over 8,000 characters, the builder says so in plain words and offers the PDF instead.
- **What the page shows:** the title, the point, the figures, each source and date, and "Made with Glyph kit" with a way to make your own. It is read-only; **Make a copy** opens it in the builder.
- **Safety:** every word in a spec is drawn as text, which `render/html.mjs` and `render/page.mjs` already escape. A link page ignores a design-system map's stylesheet address and links to nothing a spec names.
- **For agents:** `glyph-kit link spec.json` prints the link, so an agent can hand its user a link instead of a file.

### 2. Images that paste anywhere

- **Copy image** puts a PNG on the clipboard, with the figure's description and its link as plain text beside it. It pastes into Slack, Google Docs and Slides, Keynote, Notion and Figma.
- **Three sizes:** a message (wide, 2×), a slide (16:9 with the title and point), and a document (page width).
- `export --to png` takes `--for message|slide|doc`, so the command line gives the same sizes.
- A link page has its own preview image only when it's saved (0.6.0). A link that carries its page can't have one, because the server never sees it. That's the trade for not storing anything.

### 3. Your numbers in

- **Paste or drop.** Paste cells from a spreadsheet, or drop a CSV file onto the builder.
- **Fitting types.** The builder offers the types that fit the columns:
  - labels with one number become a bar chart;
  - dates with numbers become a sparkline or forecast;
  - steps with counts become a funnel;
  - two groups with a rate become a comparison.
- **No model.** The figure is drawn with no call to a model. The builder says so: "Your numbers stay in this browser."
- **No source, no numbers, as everywhere else.** The builder asks "Where are these numbers from?", prefilled with the file name. A figure isn't drawn until that field is filled.
- **Parsing:** tabs, commas, quoted cells, thousands separators, percentages and decimal commas are all read. A cell that can't be read is named with its row and column.

### 4. Pages in the builder

- The five layouts that already exist become pages you pick: `statusUpdate`, `readout`, `designReview`, `dashboard` and `prSummary`.
- You fill each page's slots: a sentence, short lists, and figures you made or pasted. Drag figures to reorder them.
- One page is one link and one PDF. The PDF comes from the browser's own print, using the report layout that already exists, in A4 or Letter.

### 5. The point first

- Every figure on a page needs a one-line point before the page can be sent. That point is `focus.say`, or `intent` when nothing is called out.
- The builder asks: "What should they take from this?"
- Link pages and slide-size images put the point above the figure. A reader who skims still gets it; the figure is the evidence.
- `check` reports a page figure with no point as a note, not a problem, so existing specs and single figures from the command line don't break.

**Not in 0.4.0:** storage, accounts, answers from readers.

**Tests:**

- spec → link → spec gives the same spec, byte for byte;
- a link page escapes every field, and ignores a map's stylesheet;
- the paste reader handles tabs, commas, quotes, separators, percentages, decimal commas and a cell it can't read;
- type suggestions for each column shape;
- the three image sizes;
- links over the limit are refused in plain words.

**Done when:** the five makers from the check each send a real update made with the kit, and each reader opens it without asking how.

## 0.5.0: Make it in minutes

Someone new makes the update their stakeholder expects, from a template, with their own numbers and their team's colour, without learning the types first.

### 1. Templates for stakeholder moments

- **Seven templates:**
  1. weekly status;
  2. research readout;
  3. experiment result;
  4. launch review;
  5. roadmap;
  6. quarterly review;
  7. decision needed.
- **What a template is:** a page whose slots hold SAMPLE DATA to replace, with a hint in each slot saying what a good one says.
- **Built from what exists:** they use only existing types and layouts. They're spec files the kit ships. This is the "patterns" idea from the UI-system plan, aimed at readers instead of screens.
- **No model:** a template plus pasted numbers needs no model call at all.

### 2. Ask for a decision

- **One new type, `ask`:** the question, two to four options with what each costs and what it changes, the recommendation, who decides, and by when.
- **Status:** open or decided. In 0.6.0, the reader answers it on the link.
- **Why it's new:** it's the one thing stakeholder updates need that no current type draws. `decisionLog` records decisions already made.
- **Motion:** the options arrive, then the recommendation lands last with the focus flash.

### 3. Your name and colour

- **The team's name** in the page header, drawn as text. Logos stay out, so the page stays text.
- **A colour** from one hue (the Mixed theme that already exists), or from the team's design-system map.
- **Contrast is checked** as it is today.

### 4. Edit any figure in place

- **Today** only tables of records and lists can be edited in place.
- **After 0.5.0**, on every type:
  - click any label or number to change it;
  - drag rows to reorder them;
  - add or remove a row from its edge.
- **No model.** Each change redraws with the kit's code. `read` is used where a type can be read back.
- **It should feel like direct manipulation, as the canvas decision asked:** drag and double-click first, with forms only as a fallback.

### 5. From Claude or ChatGPT

- **A remote MCP server:** one endpoint on the glyph-kit Vercel project, with four tools:
  - list the types;
  - draw a figure;
  - make a page from a template;
  - make a link.
- **Who it's for:** people who will never install a skill can ask their chat assistant for "this week's update as a Glyph kit page" and get a link back.
- **Cost:** the chat assistant writes the spec and the kit's code draws it, so this path costs nothing in drawing-model calls.
- **The skill stays** for agents that work in a folder.

**Tests:**

- each template passes `check`, fits 80 cells and is stamped SAMPLE DATA until its numbers are replaced;
- `ask` gets the usual zero, one and too-many cases;
- an in-place edit round-trips for every type;
- MCP tool calls give the same text as the command line.

**Done when:** someone who has never seen the kit makes a weekly status from a template with their own numbers in under ten minutes, first try. Time it with five new people.

## 0.6.0: Keep it current

The same link stays current week to week, readers see what changed, and they can answer.

### 1. One link, kept current

- **Two links, no accounts.** Saving a page gives a view link to share and an edit link to keep. Whoever has the edit link can change the page.
- **Versions.** Each save is a version. The view link always shows the latest, says "Updated 3 Nov", and lists earlier versions.
- **A preview.** A saved page gets a preview image, so Slack and email show the figure.
- **Saving is a choice.** Pages that live only in their link (0.4.0) keep working. The save button says in one line what is stored and where.

### 2. What changed since last time

The kit's figures are text, so two versions can be compared cell by cell. This is the property the kit already claims (a changed figure shows up as the changed line), turned into something a reader sees.

- **In the figure.** A changed value carries ▲ or ▼ and the old value beside it. New rows are marked new, and removed rows are listed under the figure.
- **At the top.** Code writes one line, such as: "3 numbers changed, 1 new risk, the decision was made."
- **In motion.** The old value steps to the new one inside the existing arrival: 40ms steps, settled within 600ms. Reduced motion shows the marks only.
- **On the command line.** `glyph-kit compare old.json new.json`, and `redraw` on Markdown gets the marks too.

```text
Sketch, not drawn by the kit yet

 Sign-up to paid    ███████████░░░░░  4.1%  ▲ from 3.6%
 Paid to month 2    █████████████░░░  82%   ▼ from 86%
 Refunds            █░░░░░░░░░░░░░░░  1.2%    no change
```

### 3. Readers answer back

- **What a reader can do** on a view link, without an account:
  - answer an `ask` by choosing an option, adding a line and typing their name;
  - leave a question on one figure.
- **Where the maker sees it:** on the edit link, and by email if they want it. The feedback function already sends email.
- **On the figure:** an answered `ask` shows "Decided by Maya, 4 Nov: option B".
- **Against spam:**
  - the anti-spam check on every answer;
  - a limit per link;
  - the maker can turn answers off or delete one.

### 4. Present from the link

- Arrow keys walk the page figure by figure, with each figure arriving as it does in decks. The point shows before the figure.
- This reuses the deck player.

**Tests:**

- save, load and version a page;
- a compare covers changed, new, removed and unchanged rows for every type with numbers;
- answers are rate-limited and can be deleted;
- the view link never exposes the edit link.

**Done when:** one maker updates the same link three weeks running, and their reader can say what changed without being told.

## The site follows the reader

- The home page and the Labs page lead with what a reader receives: a page, a link and a point. The cost study moves to a section for people using agents.
- No new slogans. Use the plain lines and labels that already exist.

## Decisions for you

1. **Storage for 0.6.0.**
   - The choice is between Vercel's own storage on the glyph-kit project and Supabase.
   - Either may need one package. Under this repo's rule, that needs your OK at the start of 0.6.0.
   - Recommendation: Vercel's storage, so the tool lives on one host. Without storage, 0.6.0 shrinks to "what changed" between two links.
2. **Accounts.** Recommendation: none through 0.6.0; edit links only. Add accounts only if people lose their edit links.
3. **Company numbers and the drawing model.** Asks in the builder go to DeepSeek's Flash model, and a team's first question will be where their numbers go. Recommendation:
   - the paste, template and MCP ways in never call that model;
   - the ask box says in one line which model it uses;
   - decide before 0.5.0 whether teams need a provider they already approve.
4. **Cost.**
   - More readers cost almost nothing, because links draw in the browser.
   - More makers using the ask box cost model calls.
   - Set a monthly cap for the drawing function before 0.4.0 goes out.
5. **The look for directors.** If the five-update check shows that the drawn page reads as a curiosity to readers, page text moves to Geist and only the figures stay drawn. Reports already work that way.
6. **One home.**
   - The drawing and feedback functions live on traykov.cc and are called across sites.
   - Recommendation: move them to the glyph-kit project before 0.6.0, so links, functions and storage are all in one place.

## How to work

The same as 0.3.0:

- the kit repo is `/Users/atraykov/glyph-kit`, and the portfolio's copies come from `npm run sync:glyph-kit`;
- one workstream at a time with one writer, one commit each, and no pushing (Alex reviews and pushes);
- no dependencies without approval;
- the text form of every shipped example stays byte for byte (`node tools/build-reference.mjs`, then `git diff skills/glyph-kit/reference`);
- plain words, and say "types", not "kinds".

Each release says in the changelog that existing specs need no changes, and that has to stay true.
