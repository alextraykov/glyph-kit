# Glyph kit 0.3.0: plan (for approval, nothing built)

Planned 2026-10-29 with Alex. Nothing in this plan is built. The kit is at 0.2.1 on `main`.

## Why the plan changed

Until now, 0.3.0 was going to be the canvas release. Canvases were the hero of the next launch film (`film/LAUNCH-CARRY-OVER.md` on `claude/film-020-caf141`), colour by role came with them, and the UI system was planned for 0.4.0 (`docs/ui-system-plan.md` on `claude/fervent-kilby-515266`).

On 2026-10-28 the first outside user wrote in. Alexander Balchev works only in the terminal and Neovim:

- an agent writes everything he's building as Markdown files: architecture, flow, design, data models, lifecycle and tasks;
- he reviews by commenting inside those files, like a PR, and the agent picks up the comments and rebuilds;
- he wrote his own Neovim plugin so he can watch the kit's motion without leaving the editor.

He had to build that plugin on nothing. `live` gives an HTML page or the still as text. The frames are made inside `make()` and never leave the process, so a player in any other editor has to guess at the kit's insides.

So 0.3.0 makes the file work everywhere:

1. motion plays from a file;
2. figures redraw in place in Markdown;
3. a board is a file;
4. there's a clear way to contribute.

The browser board editor stays in Labs as a prototype.

## How to work

- **Repositories.** The kit is `/Users/atraykov/glyph-kit`. The portfolio's copies (`skills/glyph-kit/`, `public/labs/glyph-kit/`) come from `npm run sync:glyph-kit` and are never edited by hand.
- **One workstream at a time**, in the order below, with one writer. Each workstream gets one commit. Don't push: Alex reviews and pushes.
- **No dependencies.** The same spec always gives the same output. Figures stay within 80 cells and use only measured glyphs.
- **Byte-stable output.** Run `node tools/build-reference.mjs`, then `git diff skills/glyph-kit/reference`. That's the gate: every shipped example draws exactly as before.
- **Copy.** Plain words, and say "types", not "kinds", in anything new.

## 1. Frames: motion as a file

**`glyph-kit frames <spec | ->`** writes JSON lines:

```text
{"glyphFrames":1,"kind":"barChart","label":"…","summary":"…","cols":64,"rows":12,"stepMs":40,"loop":null}
{"step":0,"text":"…","roles":[[2,4,6,"mute"]]}
{"step":1,"text":"…","roles":[]}
…
{"step":15,"text":"…","roles":[]}      ← the still, always the last line
```

All 61 types get frames. The kit moves them in two ways, and the file gives both the same shape:

- **54 types arrive once.** Each type has an arrival order (`arrive.mjs`, `arrive-orders.mjs`) that gives every cell a delay. Block cells step blank → ░ → ▒ → final, and text snaps in. Today only `render/arrive.mjs` uses those delays, as CSS for HTML. Frames are built from the same delays on the 40ms step (`"stepMs":40`), at most 600ms, so about 15 lines.
- **7 types keep moving:** the six processes (funnel, loop, states, queue, rollout, loading) and `abResult` with readings. Their frames are the 120ms steps the HTML player draws (`"stepMs":120`), from `frame(step, 0)` in order. Frames depend on the ones before them, so a reader can't skip ahead; the file saves players from having to replay them.
- **Roles.** Each role comes as a run: row, column, length, role, the same runs `Grid.toHtml` turns into spans. Text alone would lose the inverted flash.
- **Processes loop for good today, and no type says how long its loop is.** Each process in `motion/process.mjs` gets a `period`. The file then writes one full loop after the still, and the header says where it restarts (`"loop":{"from":…,"period":…}`).
- **Size.** Measure all 61 types. Write whole frames first, and only write changed rows if some file goes over about 200 KB.
- **`--still`** writes the header and the still only. That's also what a player shows under reduced motion.

**`glyph-kit play <spec | file.md>`** plays in the terminal:

- it redraws in place on the 120ms clock;
- roles show as reverse video and dim, with no colour;
- an arrival stops on its still, and a process loops until a key is pressed;
- `--still` prints the still;
- when the output isn't a terminal, it prints the still.

**`reference/frames.md`** explains the format on one page, written for someone building a player in another editor.

**Tests:**

- frames are byte-stable, and the last line equals `stillText`;
- every row is the same width in every frame;
- every type has a test, arrivals and processes both;
- each process loops back to its first looping frame.

## 2. Figures that redraw in place

- **A figure in Markdown keeps its spec beside it.** `render --to markdown` and `export --to md` gain `--with-spec`, which writes the spec as a `json` fence inside `<details><summary>Spec</summary>`, right after the figure. A figure can point at a spec file instead, with `<!-- glyph-kit: specs/funnel.json -->` on the line above its fence.
- **`glyph-kit redraw <file.md>`** finds every figure that has a spec and draws it again:
  - it replaces only that figure's `text` fence;
  - everything else stays byte for byte, including review comments between figures;
  - a broken spec leaves its figure alone and is reported with its line number.
- **`--check`** changes nothing. It lists figures that no longer match their spec and exits 1, for CI or a pre-commit hook.
- **Players use the same thing.** `play file.md` and a Neovim plugin find motion the same way: the spec is right there, and `frames -` turns it into frames.

**Tests:**

- a file with comments and two figures, one out of date: only that figure's fence changes;
- a file with no figures comes back unchanged;
- the inline spec and the spec file give the same figure.

## 3. Boards as files

- **Merge `canvases-0.3`** (cf01904), after bringing it up to date with 0.2.1. It has:
  - the board spec and the two example boards;
  - the grid router `areas/route.mjs`;
  - `render --to board` and `export --to canvas`;
  - `tests/board.test.mjs`.

  In 0.3.0 a board lays itself out. Things staying where they're dropped, and the `at` field that saves where, wait for the editor.
- **Motion on a board.** A `motions` list, `[{ on: "screen" | "screen.part", verb, why }]`, where verb is one of arrive, leave, answer, connect, wait or point.
  - The kit fills the rest of each intent card from the verb, the part's type and the board's links. This is the board prototype's `fill()`, moved into `areas/motion.mjs` with tests.
  - `check` points out a motion without a `why`, and a `connect` from a part with no link out.
  - The storyboard export puts each screen's motion cards under it.
- **Board figures redraw in place** like any other figure (workstream 2).

## 4. Contributing

- **`CONTRIBUTING.md`** says how to propose a type, a player or an integration. It lists:
  - the rules every figure keeps: 80 cells, measured glyphs, a label, a still for reduced motion, no dependencies;
  - the checks to run.
- **README, "Players and integrations":**
  - `play` in the terminal;
  - the HTML page;
  - his Neovim plugin, once he publishes it and says yes.
- **His testimonial comes later,** in his words, and only with his OK.
